主题: 修「单条录制点数率莫名从 25 掉到 15 Hz」, 并让你一眼看出"是游戏帧率在限速"还是"程序慢"。

### 修复

- **单条录制的点数率 15 Hz → 25 Hz(实测)**: 采样门槛和轮询周期用了同一个数(40 ms),
  而实际单帧间隔在 33~47 ms 之间抖, 凡是差一点点不到 40 ms 的帧全被判"太近"丢掉,
  下一帧就变成 80 ms —— 平均正好掉到 15 Hz。
  门槛改成轮询周期的 **0.6 倍**后实测: **511 点 / 21.13 s = 25.0 Hz**, 点间隔恒定 40 ms
  (p90 41 ms / max 49 ms)。
  - 排除过程: 与速度无关(间隔 ≤50 ms 的帧平均 39.9 km/h, >60 ms 的 40.3 km/h);
    与最小位移无关(`min_move` 一次没触发)。

### 新增

- **叠加层与状态栏显示「数据 x Hz」**: 8111 真正吐出新数据的频率, **≈ 游戏帧率**。
  三个数是 `采集 ≤ 数据 ≤ 轮询`, 一眼分清是哪一层的问题 ——
  - **轮询**掉 = 8111 那边慢了(游戏挂后台 / 切屏 / 别的程序在抢 8111);
  - 轮询正常但**数据**低 = **游戏帧率在限速**, 这时调高轮询率没有意义;
  - 数据正常但**采集**接近 0 = 车没动(位移不够不写点)。
- **轮询间隔扩到 11 档(10 Hz ~ 120 Hz)**: 补上 60 / 80 / 100 / 120 Hz。
  默认仍是 **40 ms(25 Hz)** —— 保守, 最省设备; 高帧率用户可自己往上调。
  ⚠ 8111 每渲染一帧才更新一次数据: 选得比帧率高只是重复采同一帧(位移为 0, 会被
  「最小位移」闸丢掉, **不会污染轨迹**); 选得比帧率低则点间隔会在 2 帧 / 3 帧之间跳
  (33 ms / 50 ms 交替)。
- **8111 的请求统一排队, 录制那一帧永不被打断**: 地图图片 / 校准采集改走低优先级,
  会等录制那次请求发完再发 —— 以前它们插进录制那一帧, 能把 5 ms 的 tick 拖到几十毫秒。
- **日志加了轮询诊断**: 频率掉到目标 90% 以下才写一行 `[rate]`, 附帧耗时分布、
  每帧请求数、各端点耗时。以后再报"卡 / 慢", 先看日志就能定位。

### 升级

把旧版本的 `data\` 整个拷进新目录即可, 录制内容与地图缓存都照旧读取。
