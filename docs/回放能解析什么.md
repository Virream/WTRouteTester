# 回放文件(`.wrpl`)里到底能解析出什么

> **动手前先看这一页。** 回放里"有什么、精度多少、哪些是坑"都已经实测过了 ——
> 很多看着要凿的问题其实一行就有; 反过来也有几处**看着能拿、其实是占位值**。
>
> **代码入口**: `wt81111g/wrpl_reader.py`(容器 + 包流 + 位置) ·
> `wrpl_entities.py`(ECS 档案) · `wrpl_events.py`(槽位/击杀) ·
> `replay_import.py`(→ `GlobalRecord`)
> **探针**: `tools/wrpl/probe_*.py`(签名、包流、玩家、覆盖率、阵营…)

---

## 1. 能拿到的

| 数据 | 从哪来 | 精度 / 说明 |
|---|---|---|
| **地图关卡名** | 定长头 `level` @ 8, 形如 `levels/avg_finland.bin` | 8111 **给不了**这个, 是回放最大的价值之一 |
| 对局类型 | 头 `battleType` @ 396 (`finland_Dom`) | 只是内部串, 侧栏别直接显示 |
| 环境 / 能见度 | 头 @ 524 / 652 | 目前没用上 |
| 服务器分片标记 | 头 @ 742 (`0x5A`) | 判断"要不要按分片合并" |
| 结算法偏移 | 头 @ 684 `rezOffset` | 结算 BLK 在文件尾部, **尚未解析**(见 `replay` TODO) |
| **地面单位位置** | `ptype=4`, 签名 `0xF073`(客户端) / `0xF074`(服务器) | x/z 步长 **1.7 cm**、高度 **7.6 mm**; 服务器 **24 Hz**、本地约 **1.9 Hz** |
| 飞机 / 直升机位置 | `ptype=2` FlightModel | **4 Hz**; uid 与地面**共用编号空间**(同一时刻不重复) |
| **载具身份(这是谁的车)** | `ptype=6` ECS 创建/销毁 | uid · 出生组名 · 模板名 · 存活窗口 —— 比从击杀反推可靠 |
| 玩家槽位 | `0xF02D` | 槽位 → 名字 · 军团 · 队伍 |
| 击杀事件 | `0xF058` | killer/victim 的 uid + 槽位 + 型号 + 武器 |
| 严重伤害事件 | `0xF157` | 同样带 uid + 槽位 + 型号, 用来补覆盖 |
| **战区个数** | `0xD039` 关卡对象包里的明文 `cz_circle_0N` | 个数 = 战区数 → 模式判定(3/2/1) |
| **机场坐标 + 朝向** | 同上, `tN_airfield` 条目 | 条目 = `[长度前缀模型名] + 36B 3×3 旋转矩阵 + 12B 平移(世界米)` |
| 直升机坪坐标 | 同上, `tN_helipad` / `tN_helipad_farspawn` | 低权重对局**一个都没有**(实测) |
| 各类对象的**名字** | 同上(明文串) | 见 §3 |
| 模型名里的尺寸线索 | 例: `dynaf_pg_1line_3000_universal` = 1 条线 / 3000 m | 目前只用来作旁证, 没当数据源 |

坐标轴约定(与 8111 **不同**, 见 §4 坑 3): **x = 东, y = 高度, z = 北**。

## 2. 拿不到的 —— 别白凿

| 想要的 | 为什么不行 | 替代 |
|---|---|---|
| 战区**中心坐标** | `cz_circle_0N` 的平移是**占位值**: 两张完全不同的地图都是 `(1832, 5, 2456)` | 8111 的 `capture_zone` |
| 速度 | 回放只给位置 | `位移 / 时间`, 且剔掉跳变(一帧 > 2000 m 的不算) |
| 玩家输入(WASD / 刹车 / 炮塔) | 格式里**根本没有 input 包** | 8111 + 键盘钩子(时间同源), 或不做 |
| 地面载具**朝向** | 数据里有 4×f32 四元数(+21 架历史), 但 `wrpl_reader.parse_vehicle_position` 里是 `r.skip(4*32)` **跳过未解** | 做转向分析前必须先补解 |
| 8111 的 `speed` 字段 | 那是 8111 专有的 | 同上 |

## 4. 五个必知的坑

1. **uid 会复用** —— 同一个 uid 在这一局里可能先后属于不同的车。任何"uid → 玩家"
   的绑定都必须限定在**存活窗口内**(`wrpl_entities` 做的就是这件事)。
   实测: `uid=120` 的伤害事件指向 pid 9、击杀事件指向 pid 10, 是不同时刻的两位主人。
2. **残骸会继续上报位置** —— 车被击毁后坐标还会刷一段。直接画会把线拉长、末段还会
   拐弯。必须按存活窗口把尾部裁掉(见 `replay_import` 的 `_tol_of`)。
3. **`y` 有两套含义** —— 回放的 `y` = **高度**; 8111 的 `y` = **北向**(= 回放的 `z`)。
   混一次就会画出一张"立起来"的地图。
4. **地面位置不是定长浮点** —— 是 Dagor 的 2-bit RLE 增量 + 与 32 槽历史基线逐字节
   XOR。所以"扫一遍找连续三个 4 字节浮点"这种思路一定失败, 必须走位流解码。
5. **本地回放 ≠ 服务器回放** —— 本地对**没被看见的单位**只有 ~2 Hz; 服务器分片目录
   里**单个分片只有 1/N 的数据**。想看细节就用服务器全套。

## 5. 想加新东西时的最短路径

1. **找签名**: `tools/wrpl/probe_signatures.py` —— 先把包流按 `ptype` / 签名分类计数,
   确认数据是不是真的存在, 值不值得凿;
2. **看包流**: `tools/wrpl/probe_wrpl.py` —— dump 指定包的十六进制, 对着已知明文
   (对象名 / 型号名)找结构;
3. **找明文名字**: 用 `bytes.find` 定位, **不要** `re.finditer` 扫整段 ——
   老服务器回放解压后有 42 MB, 正则会跑 1.1 秒, `find` 只要 20 ms;
4. **性能**: `BitReader.bits()` 必须按字节批量取。原来逐位 Python 循环占整个解析的
   99.6%(33 MB / 52,234 个地面包 = 230 秒), 改完是 10 秒量级;
5. **解不出来就先问 8111**: 战区中心、各类重生点这些回放只给名字的, `zones.py`
   已经能用 8111 的 `respawn_base_{tank,fighter,bomber,attack,helicopter,ucav}` 补上。

## 6. 已经验证过的结论(留个凭据, 免得重做)

- **包流恰好用尽**(零剩余字节); 飞机包间隔众数 250 ms = 4.00 Hz;
- 地面包 uid 范围 100% 合法(`下界 < 上界 ≤ 2048`), 解析失败 **0**;
- 位置样本数与上游 `wrpl-acmi` 相差 **1.2%**(151,611 vs 149,807);
- **`tN_` 前缀与队伍编号是反的**: `t1_` 属 team 2。两条独立验证 ——
  机场出生的 12 架 team1 飞机首点全部靠近 `t2_` 那侧机群; team1 的坦克 **29/29**
  首点靠 `t2_`, team2 的 **35/36** 靠 `t1_`。
  ⚠ 玩家出生组名 `tN_playerMM_K` 里的 `tN` **不是阵营**, 别混用。
- **机场坐标是真值、战区坐标是占位值**: 芬兰同一张图两种模式, `t1_airfield` 从
  `(-6289, 70, 12530)` 变到 `(-1867, 77, 8033)`(用户: "这局权重低, 机场靠前了"),
  而战区圆两个模式都是 `(1832, 2456)` 且彼此只差 14.65 m;
- **机场防空的实测质心与机场坐标吻合**: `tX_airfield_aaa_*` 的质心 `(-6358, 12414)` /
  `(11894, -7795)` 对得上 `t1_airfield` / `t2_airfield` —— 所以「用防空军阵地估跑道」
  这条近似是站得住的(见 `replay_import._airfields_from_ecs`);
- 同一辆车曾被数成多辆、寿命重叠 —— 那是 uid 复用没按存活窗口限定造成的, 已修。
