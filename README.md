# WTRouteTester — 战争雷霆 · 跑图线路测试器

基于战争雷霆官方 **8111 本地 HTTP 接口** 与**回放文件**的小工具: 记录"重生后多久到达某位置"
的线路, 多条对比、按绝对时间轴回放; 也可以直接从一局回放里解出**两队全部地面单位**的
路线, 用来复盘谁在什么时间走了哪条路。

当前版本 **v1.3.0**(2026-10-26), 更新日志见 [`CHANGELOG.md`](CHANGELOG.md)。

## 下载

到 [Releases](https://github.com/Virream/WTRouteTester/releases) 下
`WTRouteTester_<版本>_win64.zip`, **解压即用**(无需安装)。

- 程序把数据写在 exe 同级的 `data\`(`routes.json` 录制的线路 + `maps\` 地图缓存);
  zip 里**不含** `data\`, 首次运行自动创建;
- 升级时把旧的 `data\` 一起拷进新目录即可, 录制内容不会丢。

## 使用说明

线路有两个来源: **8111 实况录制**(单条路线, 边跑边录) 与 **回放文件解析**
(整局两队所有地面单位, 一次导入)。

### 单条路线录制

用来测一辆车的加速度、转弯半径、到地图某个点位的耗时等。

1. 进入对局(**自定义 / 试车场 / 实战**均可);
2. 点 **「开始录制轨迹」** 或按 **`F5`** 开始;
3. 跑完后按 **`F6`** 或点 **「结束录制轨迹」** 保存;
4. 保存后把鼠标移到地图上的**采集点**上, 左下角会浮出一个信息框, 显示
   载具型号、该点的时间、速度、转弯半径等。

**「以速度从零变化的时刻作为起始点」**: 只对单条路线生效。勾上后, 时间轴的 0 点
取"速度开始从零变化的那一刻", 也就是从**车子开始移动**时算起(而不是点录制的那一下)。

### 回放文件解析(整局所有玩家)

底部两个按钮: **「从录像中获取路线(本地)」** 与 **「从录像中获取路线(服务器)」**。
一次就能解出这局**两队全部地面单位**的轨迹 —— 玩家名、阵营、载具型号、阵亡时刻都有,
而且回放自带战斗时钟, **不用对轴、也不用观战两次**。

| 来源 | 选什么 | 采样率 |
|---|---|---|
| 本地 | 游戏内「保存回放」得到的 `.wrpl` 文件 | 被看见的单位 ~24 Hz; **没被看见的只有 ~2 Hz** |
| 服务器 | 官网下载的分片**所在文件夹**(整套放同一个目录) | 24 Hz |

- **想看路面细节、悬挂起伏就用服务器回放**; 只要大致走位, 本地回放就够;
- 不要只选服务器回放的**一个分片** —— 单个分片只有 1/N 的对局数据;
- 支持**批量**: 一次选多个 `.wrpl` 或多个文件夹, 逐个解析, 进度框可以取消。
  每局生成**一个**条目, 排在它所属模式下的单条轨迹之后;
- **地图名取自回放头**(`levels/avg_xxx.bin`) —— 这是 8111 给不了的。第一次遇到某张图时,
  到「地图管理」的 **「可选: 回放关卡代号」** 列里把它指到 8111 那份缓存图上,
  之后两者共用同一张底图与同一套校准; 改回「(不关联)」即可撤销(这一列是**可逆**的);
- 阵亡时刻来自回放里的**击杀记录 + 实体档案**: 残骸会被继续上报, 所以程序会按存活窗口
  把尾部裁掉 —— 比 8111 的“图标消失”准。

### 注意事项

- **不要随意改采样率设置**: 除非遇到稳定性问题。已知 8111 偶尔**漏报 hudmsg**,
  漏报至今无法 100% 消除(这是 8111 的 bug);
- 8111 的数据更新速度似乎**和游戏帧数有关**: 录制时尽量保证游戏帧数**高于**你设置的采样率;
- **回放解析出来的速度是按位移算的**(回放里没有 8111 那种现成的 `speed`), 有偏差,
  不要完全相信(单条路线录制没有这个问题);
- 8111 **不提供转弯半径**, 单条路线录制里的转弯半径是**算法算出来的**:
  `5 M ±15%` 中的 `±15%` 是**置信度**, 数值越低, 前面算出的转弯半径越可靠。

## 主要功能

- **单条线路录制**: 25Hz 采样, 按速度配色, 可打时间标记, 算转弯半径;
- **从回放导入整局**: 选本地 `.wrpl` 或服务器回放分片文件夹, 一次解出两队全部地面单位的
  轨迹(玩家名 / 阵营 / 载具型号 / 阵亡时刻), 自带战斗时钟, 无需对轴;
- **地图与战区**: 8111 不给地图名, 用**图片内容指纹**当身份(自动把同图不同分辨率认成一张),
  名字自己起; 回放的**关卡代号**可以指到某张 8111 地图上, 两者共用底图与校准;
  「地图管理」里能改名、看预览、**校准地图位置**(回放的米制坐标靠它对齐到底图);
- **侧栏三层**: 地图 → 模式 → 线路/整局条目。模式按战区数量判定(3 个 = 战区控制,
  2 个 = 战区攻陷, 1 个 = 战区争夺), 大图/小图与战区争夺的随机点位都归在同一行;
  眼睛图标控制显示, 选中即回放, 跨地图/跨模式的多选会被挡下(基准 + 图钉);
- **看得清的选中**: 双击定基准; Shift 框选把整局条目带进来时, 那些被动选中的线路行
  也会刷选中色, 信息区写明「待回放 N 条(其中整局 M 条)」;
- **录制叠加层**: 录制时显示实际采样率、轮询频率、点数、标记数;
- **轮询率可调**: 菜单「设置 → 轮询间隔」里, 单条录制 / hudmsg 各自独立
  (默认 40 / 2000 ms); 信息区里的「轮询 xx Hz」是**实际**频率;
- **GPU 画布**: 装了 `pygfx` + `wgpu` 时用 GPU 画(见 `requirements-gl.txt`),
  否则自动回退软件渲染。

## 数据来源与反作弊

只读游戏自带的 `http://127.0.0.1:8111` 本地接口,**不读取、不修改任何游戏文件**
(不碰安装目录、日志、存档), 不注入进程 —— 纯外部轮询。

## 快捷键(默认)

| 键 | 动作 |
|---|---|
| `F5` | 开始录制轨迹 |
| `F6` | 结束录制轨迹(保存) |
| `F7` | 标记当前位置 |

可在菜单「快捷键」里改; 程序不拦截按键(游戏也会收到), 建议绑游戏里没用的键。

## 从源码运行 / 打包

```powershell
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt          # GPU 画布另加 requirements-gl.txt
.venv\Scripts\python route_tester.py                   # 直接运行

.\build_route_tester.ps1                               # 打包 onedir 目录版
```

打包前请**关掉正在运行的程序**, 否则 `dist\WTRouteTester\data` 被占用会中止
(脚本会保护该目录, 绝不删用户的录制数据)。
